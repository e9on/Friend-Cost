# 친구비 측정기

카카오톡 1:1 대화 캡처를 분석해 두 사람의 관계를 숫자와 리포트로 보여주는 웹 서비스.

계정도, 기록도, 영구 저장도 없다. 결과는 20분 뒤 사라진다.

## 빠르게 돌려보기

```bash
# 백엔드
cd backend
py -3.10 -m venv .venv
.venv/Scripts/python.exe -m pip install -e ".[dev]"
.venv/Scripts/python.exe -m uvicorn app.main:app --reload

# 프론트엔드 (다른 터미널)
cd frontend
npm install
npm run dev
```

http://localhost:5173 에서 아무 PNG나 올려보면 된다. 스텁 OCR이 합성 대화를 만들어 파이프라인 전체가 돈다.

## 이 프로젝트를 이해하는 다섯 가지

문서를 다 읽기 전에 알아두면 나머지가 쉽게 읽힌다.

### 1. 화자는 말풍선의 좌우 위치로만 구분된다

카카오톡 캡처에는 "누가 보냈는지"를 알려주는 텍스트가 없다. 내 말풍선은 오른쪽, 상대 말풍선은 왼쪽에 붙는다는 것이 유일한 단서다.

그래서 **OCR 엔진은 좌표를 반환해야 한다.** 정확도가 아무리 높아도 좌표가 없으면 채택할 수 없다. 이건 순위가 아니라 자격 요건이다.

판별은 중심점이 아니라 **좌우 여백을 비교**한다. 긴 메시지는 화면 폭의 70%를 차지해서 중심점이 가운데로 몰리기 때문이다.

### 2. 점수는 코드가 계산하고, LLM은 의미만 읽는다

LLM은 감정·노력·갈등 같은 **의미**를 0~100으로 판단할 뿐이다. 비율, 평균, 답장 속도는 전부 코드가 센다.

같은 대화에 항상 같은 점수가 나와야 하기 때문이다. 계산을 LLM에 맡기면 그 보장이 사라진다.

### 3. 우리가 다루는 건 남의 사적인 대화다

업로더는 자기 대화라고 생각하지만, 캡처의 절반은 **동의하지 않은 상대방이 쓴 글**이다.

여기서 여러 결정이 나온다. 원문을 로그에 남기지 않고, 결과 응답에도 담지 않고, 리포트 Agent에게는 아예 주지 않는다. **입력을 학습에 쓰는 무료 티어는 아무리 싸도 쓰지 않는다.**

### 4. 초기에는 비용이 문제가 아니지만, OCR이 곧 지배한다

월 100건 기준 약 3,000원. 목표였던 3개월 10만 원의 6% 수준이다. 이 구간에서는 **가격이 아니라 품질과 개인정보로 고른다.**

다만 규모가 커지면 달라진다. LLM은 Groq 무료 티어가 월 15,000건까지 덮지만 **OCR은 건당 과금이라 선형으로 오른다.** 월 5,000건이면 Vision 5만 원, CLOVA 24만 원이다. 컨테이너 내장 OCR 전환점은 월 약 1,141건이다.

저가 모델의 진짜 위험은 실패가 아니라 그럴듯한 오답이다. 어떤 대화를 넣어도 친밀도가 60~70만 나오는 모델은 관계를 못 읽는 것인데, 그건 오류로 드러나지 않고 사용자는 그 숫자를 믿는다.

### 5. 문서와 코드가 어긋나면 테스트가 깨진다

`backend/tests/test_docs_consistency.py` 가 문서의 숫자를 파싱해 코드의 상수와 비교한다. TTL을 코드에서만 바꾸면 즉시 걸린다.

사람이 지키는 규칙은 언젠가 깨지므로 기계가 지키게 했다.

## 실제 모델 붙이기

교체 지점은 설정뿐이다.

```bash
FC_LLM_PROVIDER=groq              # stub | anthropic | groq | deepseek | together | openrouter
FC_LLM_MODEL=openai/gpt-oss-120b
FC_LLM_API_KEY=...
FC_LLM_REASONING_EFFORT=low       # 추론 모델만. gpt-oss는 low, qwen은 none

FC_OCR_ENGINE=google_vision   # stub | google_vision
FC_OCR_API_KEY=...
```

**추론 모델에는 `FC_LLM_REASONING_EFFORT` 를 반드시 채운다.** 비워두면 모델이 `reasoning` 에 출력 예산을 다 쓰고 본문을 못 내놓아 400이 난다. 허용값이 계열마다 다르다(gpt-oss: `low`/`medium`/`high`, qwen: `none`/`default`).

붙이기 전에 실측한다.

```bash
cd backend
.venv/Scripts/python.exe tools/evaluate_llm.py --provider groq --model openai/gpt-oss-120b --key $GROQ_KEY
```

후보와 절차는 [AI 모델 선정 보고서](mdfiles/AI-모델-선정-보고서.md) 8장에 있다.

## 테스트

```bash
cd backend  && .venv/Scripts/python.exe -m pytest
cd frontend && npm test
```

핵심 로직은 테스트를 먼저 쓰고 구현했다. 점수 규칙 13장의 손계산 예제가 그대로 회귀 테스트 고정값이다.

`tests/test_docs_consistency.py` 는 문서·백엔드·프론트의 값이 서로 어긋나지 않는지 본다. 업로드 제한을 프론트에서만 바꿔도 여기서 걸린다.
