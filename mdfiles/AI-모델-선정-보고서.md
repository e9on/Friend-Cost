> **4장(OCR)과 6장(비용)은 `OCR-재선정-보고서.md` 가 대체한다.** 이 문서는 월 100건 기준으로만 비용을 계산해 "비용은 문제가 아니다"라고 결론 냈는데, 규모를 넣어 다시 계산하니 **OCR이 비용을 지배**하는 것으로 드러났다. LLM 부분(3장·5장)은 그대로 유효하다.

## 1. 결론 먼저

**무료 티어 대부분은 이 서비스에 쓸 수 없다.** 성능이나 한도 때문이 아니라 **데이터 정책** 때문이다.

우리가 다루는 것은 사용자 본인의 데이터가 아니라 **대화 상대방의 사적인 메시지**다. 입력을 학습에 쓰거나 사람이 검토할 수 있는 티어에 그 대화를 보내는 것은, 기준 명세 5장의 원문 보호 원칙을 정면으로 어긴다. 월 2,000원을 아끼려고 감수할 위험이 아니다.

이 기준을 통과한 후보만 추리면 다음과 같다.

| 구분 | 1순위 | 대안 |
| --- | --- | --- |
| OCR | Google Cloud Vision | Naver CLOVA OCR (한국어 정확도 우선 시) |
| LLM | **Groq `qwen/qwen3.8-27b`** (2026-08-26 실측으로 확정) | `qwen/qwen3.6-27b` (더 빠름), Claude Haiku 4.5 (품질 기준선) |
| 볼륨 증가 시 | PaddleOCR 컨테이너 내장 OCR | 저가 유료 모델로 전환 |

## 2. 이 서비스만의 선정 기준

일반적인 "성능 대비 가격" 비교로는 답이 나오지 않는다. 우리에게는 네 가지 제약이 있다.

### 2.1 좌표는 타협 불가 (OCR)

카카오톡 캡처에서 화자는 말풍선의 **좌우 위치**로만 구분된다. 좌표를 주지 않는 엔진을 쓰면 먼저 연락 비율·평균 답장 속도·연락 균형도·손절 위험도가 전부 계산 불가능해진다.

**정확도가 아무리 높아도 좌표가 없으면 탈락이다.** 이건 순위가 아니라 자격 요건이다.

### 2.2 제3자의 사적 대화 (양쪽 모두)

업로더는 자기 대화를 올리지만, 그 안에는 **동의하지 않은 상대방의 메시지**가 들어 있다. 일반적인 SaaS보다 기준이 높아야 한다.

- 입력을 **학습에 사용하지 않을 것**
- 사람이 검토하지 않을 것
- 보관하지 않거나, 보관 기간이 짧고 명시적일 것

### 2.3 한국어

카카오톡 대화는 한국어다. 반말·줄임말·자음 표현(`ㅇㅇ`, `ㅋㅋ`)·이모티콘이 섞인, 문어체와 거리가 먼 텍스트다. 영어 벤치마크 점수는 참고치일 뿐이다.

### 2.4 JSON 스키마 준수

Analysis Agent는 정해진 스키마로만 답해야 한다. 스키마를 자주 어기는 모델은 재시도가 잦아져 **실질 비용이 표시 가격보다 높아진다.** 우리 구현은 재시도를 1회만 허용하므로, 스키마 준수율이 낮으면 그대로 실패율이 된다.

## 3. 무료 티어의 함정

조사 중 가장 중요했던 발견이다.

| 제공자 | 무료 티어 한도 | 입력을 학습에 쓰는가 | 판정 |
| --- | --- | --- | --- |
| **Google Gemini** | 1,500 요청/일, 1M TPM | **쓴다. 사람 검토 가능** | **탈락** |
| **Mistral** | 월 약 10억 토큰 | **학습 동의가 사용 조건** | **탈락** |
| **Groq** | 8,000 TPM, 1,000 요청/일 (2026-08-26 실측) | **쓰지 않음 (무료·유료 동일)** | **통과** |
| Cerebras | 약 100만 토큰/일 | 공개 정보 불충분 | 확인 필요 |
| OpenRouter 무료 모델 | 모델별 상이 | 백엔드 제공자에 따라 다름 | 개별 확인 |

Gemini는 무료 티어 성능만 보면 최선의 후보였다. 1,500 요청/일이면 우리 초기 규모를 통째로 덮고, 뒤에 나오듯 OCR까지 겸할 수 있다. 그런데 **무료 티어의 입력은 Google 제품 개선에 쓰이고 사람이 검토할 수 있다.** 유료 티어로 올리면 학습에 쓰지 않는다.

즉 Gemini는 "무료라서 탈락"이 아니라 **"무료 티어라서 탈락"** 이다. 유료로 쓰면 유효한 후보다.

> EEA·스위스·영국 사용자는 무료 티어에도 유료 약관이 적용된다. 한국 사용자 대상 서비스에는 해당하지 않는다.

Groq은 예외적으로 **무료 티어에서도 학습에 쓰지 않는다고 명시**한다. 계정 단위 정책이라 티어로 갈리지 않는다. 기본적으로 입출력을 보관하지도 않는다.

## 4. OCR 후보

### 4.1 비교

| 후보 | 한국어 정확도 | 좌표 | 무료 한도 | 초과 비용 | 비고 |
| --- | --- | --- | --- | --- | --- |
| **Naver CLOVA OCR** | 인쇄체 97%+ (최상위) | 제공 | 월 1,000건 | 약 10원/건 | 한국어 특화 |
| **Google Cloud Vision** | 상위권, 속도 최상 | 제공 | 월 1,000페이지 | 약 2원/건 | 구조화 추출은 없음 |
| Azure Document Intelligence | 상위권 | 제공 | 제한적 | — | 속도 우수 |
| **PaddleOCR (컨테이너 내장 OCR)** | 95%+ (아시아 문자 강점) | 제공 | 무제한 | 서버 비용 | torch 불필요, CPU 처리량 좋음 |
| EasyOCR (컨테이너 내장 OCR) | 95%+ | 제공 | 무제한 | 서버 비용 | 저대비 이미지에 강함 |
| Tesseract | 낮음 | 제공 | 무제한 | 서버 비용 | 비라틴 문자·복잡한 레이아웃에 약함 |

Tesseract는 딥러닝 기반 엔진 대비 실사용 문서에서 정확도가 크게 떨어져 **후보에서 제외**한다.

### 4.2 컨테이너 내장 OCR의 숨은 비용

PaddleOCR은 라이선스 비용이 0이지만, **상시 실행 컨테이너가 필요하다.** 기준 명세 6장이 전제한 "요청 없을 때 인스턴스가 0으로 내려가는" 배포와 충돌한다.

- 이미지가 무거워져 콜드 스타트가 길어진다
- 최소 인스턴스를 1로 두면 유휴 과금이 생긴다

**월 수백 건 규모에서는 건당 과금 API가 더 싸다.** 볼륨이 커진 뒤에 전환하는 것이 맞다. 기준 명세 8장이 이미 그렇게 적어두었고, 이번 조사도 같은 결론이다.

### 4.3 뜻밖의 후보 — Vision LLM이 OCR을 겸하는 방법

Gemini 2.5 Flash는 이미지에서 **텍스트와 bounding box를 함께** 반환한다. 좌표는 `[y0, x0, y1, x1]` 형식이며 이미지 크기와 무관하게 **0~1000으로 정규화**된다.

우리 화자 판별은 좌우 여백을 비교하는 방식이라, **정규화 좌표를 그대로 쓸 수 있다.** `page.width = 1000` 으로 두면 코드 변경 없이 동작한다.

이 방식의 장단점은 이렇다.

| | 내용 |
| --- | --- |
| 장점 | OCR과 파싱을 한 번에. 별도 OCR 계약 불필요 |
| 단점 | 이미지 토큰 비용이 텍스트보다 훨씬 비싸다 |
| 단점 | "저가 모델 우선" 원칙과 충돌 가능 |
| 단점 | **무료 티어는 개인정보 문제로 쓸 수 없다** |

지금 당장 채택할 근거는 약하지만, **OCR 계약이 번거롭거나 정확도가 안 나올 때의 우회로**로 기록해둔다.

### 4.4 OCR 권고

1. **Google Cloud Vision을 먼저 검증한다.** 좌표가 확실하고, 무료 한도가 우리 초기 규모를 덮으며, 초과 비용도 CLOVA의 1/5 수준이다.
2. **화자 판별 정확도가 기준에 못 미치면 CLOVA로 옮긴다.** 한국어 인쇄체 정확도가 가장 높다. 비용은 약 5배지만, 지표가 틀리면 서비스가 성립하지 않는다.
3. ~~월 2,000건을 넘어가면 PaddleOCR 컨테이너 내장 OCR을 재검토한다.~~
   **정정: 배포처에 따라 다르다. Cloud Run 상시 실행이면 월 약 2,831건, 저가 VPS면 약 1,141건.** 자세한 계산은 `OCR-재선정-보고서.md` 1장.

## 5. LLM 후보

### 5.1 가격 (100만 토큰당)

| 모델 | 입력 | 출력 | 개인정보 |
| --- | ---: | ---: | --- |
| Ling-2.6-flash | $0.01 | $0.03 | 확인 필요 |
| Qwen3.7 Flash | $0.03 | $0.13 | 확인 필요 |
| Gemini 2.5 Flash-Lite | $0.10 | $0.40 | 유료 티어는 학습 안 함 |
| DeepSeek-V4 | $0.14 | $0.28 | 확인 필요 |
| Mistral Small 4 | $0.15 | $0.60 | 유료 티어 |
| Claude Haiku 4.5 | $1.00 | $5.00 | 학습 안 함 |
| Claude Sonnet 5 | $2.00 | $10.00 | 학습 안 함 |
| Claude Opus 5 | $5.00 | $25.00 | 학습 안 함 |
| Groq (Llama 3.3 70B 등) | 무료 티어 | 무료 티어 | 학습 안 함 |

2026년 8월 기준 주류 API의 입력 가격 하한은 100만 토큰당 약 $0.20 근처까지 내려왔다.

### 5.2 우리 워크로드 기준 건당 비용

토큰 압축을 적용한 값이다. 분석 호출 입력 4,500 + 출력 1,000, 리포트 호출 입력 2,000 + 출력 600. 환율 1,400원.

| 모델 | 건당 | 월 100건 | 월 500건 |
| --- | ---: | ---: | ---: |
| Groq 무료 | **0원** | 0원 | 한도 초과 |
| Ling-2.6-flash | 0.16원 | 16원 | 80원 |
| Qwen3.7 Flash | 0.6원 | 56원 | 280원 |
| Gemini 2.5 Flash-Lite | 1.8원 | 180원 | 900원 |
| DeepSeek-V4 | 1.9원 | 190원 | 950원 |
| Claude Haiku 4.5 | 20원 | 2,000원 | 10,000원 |
| Claude Sonnet 5 | 41원 | 4,100원 | 20,500원 |

**Groq 무료 티어의 병목은 요청 수가 아니라 분당 토큰이다.**

2026-08-26에 응답 헤더로 실측한 값이다.

| 헤더 | 값 | 우리에게 뜻하는 것 |
| --- | --- | --- |
| `x-ratelimit-limit-requests` | 1,000 / 일 | 분석 1건에 LLM 2회 → **하루 500건** |
| `x-ratelimit-limit-tokens` | **8,000 / 분** | 분석 1건이 약 2,600토큰 → **분당 3건** |

하루 총량은 500건이지만 **순간 처리량은 분당 3건**이다. 이 둘을 섞으면 안 된다. 하루 500건을 근거로 "초기 규모에서는 무제한"이라고 적었던 것은 총량만 본 것이다.

이 값이 배포 설계에 직접 걸린다. `concurrent_analysis_limit` 이 3이면 세 건이 동시에 시작할 때 분석 호출만으로 약 7,800토큰을 한꺼번에 쓴다. 8,000 바로 앞이고 뒤따르는 리포트 호출이 넘긴다. 그래서 Provider가 429를 한 번은 기다렸다 다시 던진다(`app/ai/provider/openai_compatible.py`). 재시도가 없으면 사용자는 자기 잘못이 아닌 이유로 분석에 실패한다.

실측 중 이 한도를 무시하고 던졌더니 성공률이 67~83%로 떨어졌다. **그 숫자는 모델 품질이 아니라 우리 요청 속도를 잰 것이다.** 그대로 모델을 골랐다면 멀쩡한 후보를 떨어뜨렸을 것이다.

### 5.3 저가 모델의 진짜 위험

표시 가격만 보면 Claude Haiku가 Qwen Flash보다 33배 비싸다. 하지만 우리 작업의 성격을 보면 단순 비교가 어렵다.

Analysis Agent가 하는 일은 **한국어 반말 대화의 관계적 뉘앙스를 읽어 정해진 JSON으로 뱉기**다. 소형 모델이 가장 약한 두 가지가 겹쳐 있다.

- 스키마를 어기면 재시도 1회, 그래도 실패하면 분석 자체가 실패한다
- 뉘앙스를 못 읽으면 값이 뭉개져 모든 사용자에게 비슷한 결과가 나온다

두 번째가 특히 위험하다. **틀린 결과는 오류로 드러나지 않는다.** 그럴듯한 숫자가 나오고, 사용자는 그것이 자기 관계를 반영한다고 믿는다.

그래서 **가격순으로 고르지 않고 실측으로 고른다.**

### 5.4 LLM 권고

1. **Groq 무료 티어로 시작한다.** 개인정보 조건을 통과하는 유일한 무료 후보이고, 초기 규모를 덮으며, 비용이 0이다.
2. **Claude Haiku 4.5를 품질 기준선으로 둔다.** 같은 대화를 두 모델에 넣어 결과가 얼마나 갈리는지 본다. 차이가 작으면 Groq을 쓰고, 크면 Haiku 비용(월 2,000원)을 감수한다.
3. 월 500건을 넘으면 Groq 한도를 벗어나므로 Gemini Flash-Lite 유료 티어나 DeepSeek로 옮긴다.

## 6. 비용 시뮬레이션

월 100건, 이미지 5장 기준.

| 항목 | Groq + Vision | Haiku + Vision | Haiku + CLOVA |
| --- | ---: | ---: | ---: |
| 서버 | 0원 | 0원 | 0원 |
| OCR | 0원 (무료 한도) | 0원 (무료 한도) | 0원 (무료 한도) |
| LLM | 0원 | 2,000원 | 2,000원 |
| **월 합계** | **0원** | **2,000원** | **2,000원** |
| **3개월** | **0원** | **6,000원** | **6,000원** |

목표가 3개월 10만 원이었으니 **어느 조합을 골라도 목표의 6% 이하**다.

월 500건으로 늘면 이렇게 바뀐다. 이미지 2,500장이라 OCR 무료 한도를 넘는다.

| 항목 | Vision | CLOVA |
| --- | ---: | ---: |
| OCR (1,500장 초과분) | 약 3,000원 | 약 15,000원 |
| LLM (Haiku) | 10,000원 | 10,000원 |
| **월 합계** | **13,000원** | **25,000원** |

이 구간부터 OCR 선택이 비용을 좌우한다.

> **이 표는 월 500건까지만 본 것이다.** 더 큰 규모에서는 OCR이 전체 비용을 지배한다. 월 20,000건이면 CLOVA 99만 원, Vision 21만 원, 컨테이너 내장 OCR 4.5만 원이다. `OCR-재선정-보고서.md` 1장과 `backend/tools/cost_model.py` 참조.

## 7. 판단 요약

- **비용은 이미 문제가 아니다.** 어느 조합이든 초기 예산의 10% 이하다. 그러므로 **가격이 아니라 품질과 개인정보로 고른다.**
- **무료 티어를 쓰려면 Groq이 사실상 유일하다.** 학습 미사용을 명시하는 곳이 거기뿐이다.
- **OCR은 좌표가 자격 요건이고, 그다음이 한국어 정확도다.** 비용은 세 번째다.
- **저가 LLM의 위험은 실패가 아니라 그럴듯한 오답이다.** 반드시 실측한다.

## 8. 검증 계획

숫자로 고르지 말고 같은 입력으로 재본다.

### 8.1 준비물

실제 카카오톡 1:1 대화 캡처 **20세트**. 관계 유형이 섞이도록 고른다.

- 자주 연락하는 친구 / 뜸해진 친구
- 한쪽이 주로 먼저 거는 관계 / 균형 잡힌 관계
- 짧은 대화 / 긴 대화
- 이모티콘·사진이 많은 대화

### 8.2 OCR 평가 항목

| 항목 | 기준 | 왜 보는가 |
| --- | --- | --- |
| **화자 판별 정확도** | 오분류 메시지 비율 | 틀리면 지표 절반이 무너진다 |
| 시각 인식률 | `timeSource != unknown` 비율 | 답장 속도·세션 분할의 전제 |
| 텍스트 정확도 | 한글 오인식률 | LLM 입력 품질 |
| 처리 시간 | 이미지 1장당 | 실행 시간 제한 60초 |
| 건당 비용 | 원 | 볼륨 증가 시점 판단 |

`tests/fixtures/kakao.py` 의 합성 픽스처가 비교 기준이다. 실제 엔진 출력이 이 픽스처와 같은 성질(좌우 정렬, 시각 라벨 위치)을 가지면 Parser가 그대로 동작한다.

### 8.3 LLM 평가 항목

| 항목 | 기준 |
| --- | --- |
| **순위 일치도** | 기대한 관계 순서를 지키는가. 65% 미만이면 탈락 |
| **결과 분산** | 값을 얼마나 벌리는가. 순위가 같다면 편차가 큰 쪽을 고른다 |
| 스키마 준수율 | 1차 시도 성공 비율 |
| 재현성 | 같은 입력 3회 반복 시 점수 편차 |
| 한국어 리포트 품질 | 어색한 번역투, 존댓말 혼용, 사실과 다른 서술 |
| 지연 | 호출당 초 |
| 건당 비용 | 원 |

**순위 일치도가 가장 중요하다.** 스키마를 지키고 문장이 매끄러워도, 절친과 일방적 관계를 구분하지 못하면 그 모델은 쓸 수 없다. 그런 모델은 오류를 내지 않으므로 눈에 띄지 않고, 사용자는 그 숫자가 자기 관계를 반영한다고 믿는다.

표준편차만 보면 안 되는 이유는, **값이 널뛰기만 해도 편차는 커지기 때문이다.** 관계를 구분하는지 보려면 순서가 맞는지를 봐야 한다. `tools/samples.py` 가 관계 여섯 종을 기대 순위와 함께 만들고, `concordance()` 가 방향이 맞는 쌍의 비율을 센다.

모든 관계에 같은 값을 낸 모델은 "틀리지 않았다"가 아니라 **"판단하지 않았다"** 이므로 분모에서 빼고 "잴 수 없음"으로 표시한다. 그렇게 하지 않으면 일치율이 부풀어 오른다.

**실제 캡처가 없어도 잴 수 있다.** 8.1의 캡처 20세트는 있으면 더 좋지만 전제 조건이 아니다. 아래 실측이 그 증거다.

### 8.4 진행 순서

도구가 준비되어 있다. `backend/tools/` 에 있다.

**1단계 — 캡처를 모은다**

대화 한 건을 디렉터리 하나에 담고, 파일명에 번호를 붙인다. **파일명 순서가 시간 순서**로 쓰인다.

```text
caps/
├── 대화01/  01.png 02.png 03.png
├── 대화02/  01.png 02.png
└── ...
```

**2단계 — OCR 후보를 잰다**

```bash
python tools/evaluate_ocr.py --images caps/대화01 --engine google_vision --key $KEY     --out fixtures/대화01.json --review review/대화01.txt
```

블록 좌우 판별 비율, 시각 복원률, 처리 시간이 나온다. 한쪽 화자만 판별되거나 시각 복원률이 낮으면 경고를 띄운다.

**화자 판별 정확도는 자동으로 잴 수 없다.** 정답이 없기 때문이다. `--review` 로 나온 파일을 훑어 대화가 "나 → 상대 → 나"로 자연스럽게 이어지는지 본다. 한 사람이 혼자 묻고 답하는 것처럼 보이면 판별이 틀린 것이다.

> 검토 파일에는 대화 원문이 들어간다. **확인이 끝나면 지운다.**

**3단계 — 저장된 픽스처로 LLM 후보를 잰다**

OCR을 다시 돌릴 필요가 없다. 2단계에서 저장한 `OcrPage` JSON을 그대로 쓴다.

후보를 나란히 놓고 표 하나로 본다. 따로 돌려 결과를 머릿속에서 비교하면 성공률처럼 눈에 띄는 지표만 보고 정하게 된다.

```bash
python tools/compare_llm.py --key $GROQ_KEY
python tools/compare_llm.py --key $GROQ_KEY --fixtures fixtures/
```

**분당 토큰 한도에 맞춰 간격을 둔다.** 기본값이 그 값이다. 무시하고 던지면 429가 쏟아지고, 그러면 성공률이 모델 품질이 아니라 요청 속도를 재게 된다.

모델 하나를 자세히 보려면:

```bash
python tools/evaluate_llm.py --provider groq --model qwen/qwen3.8-27b     --reasoning-effort none --profiles --delay 20 --key $GROQ_KEY
```

**추론 모델에는 `--reasoning-effort` 를 반드시 준다.** 비우면 추론이 출력 예산을 다 먹고 본문을 못 내놓아 400이 난다. 허용값은 계열마다 다르다(3.3 표).

**4단계 — 확정한다**

```bash
FC_OCR_ENGINE=google_vision
FC_OCR_API_KEY=...
FC_LLM_PROVIDER=groq
FC_LLM_MODEL=qwen/qwen3.8-27b
FC_LLM_API_KEY=...
FC_LLM_REASONING_EFFORT=none
```

확정 후 이 문서와 `운영-보안-법적고지-명세.md` 4.3의 제3자 제공 목록을 갱신한다. 코드만 바꾸고 고지를 방치하면 사실과 다른 안내가 된다.

## 9. 미확인 항목

정직하게 남겨둔다. 아래는 이번 조사로 확정하지 못했다.

- **Naver CLOVA OCR의 좌표 응답 형식.** 좌표를 제공한다는 것은 확인했으나 필드 구조는 공식 문서 확인이 필요하다. 우리 `OcrBlock` 으로 변환 가능한지가 채택 조건이다.
- **CLOVA 무료 한도.** 자료마다 월 1,000건과 5,000건으로 엇갈린다. 계약 전 확인이 필요하다.
- **Cerebras·DeepSeek·Ling의 데이터 정책.** 가격은 매력적이나 학습 사용 여부를 확인하지 못했다. 확인 전에는 후보로 올리지 않는다. Qwen 은 Groq 위에서 돌리므로 Groq 정책을 따른다.
- ~~**Groq의 한국어 성능.**~~ 2026-08-26 실측으로 해소했다. 9장 참조. 다만 합성 대화 기준이며 실제 캡처로 다시 재야 한다.
- **Groq의 vision 모델 지원 여부.** OCR을 겸하게 할 수 있는지는 확인하지 못했다.
