## 1. 문서 목적

이 문서는 서비스를 실제 사용자에게 공개하기 전에 갖춰야 할 **고지, 동의, 보안 조치**를 정의한다.

기술적으로 잘 만들어도 이 문서의 항목이 비어 있으면 공개할 수 없다. 이 서비스는 **동의하지 않은 제3자의 사적 대화**를 처리하기 때문이다.

## 2. 이 서비스의 특수한 위치

일반적인 웹 서비스와 결정적으로 다른 점이 하나 있다.

```text
일반 서비스:  사용자가 자기 데이터를 올린다
친구비 측정기: 사용자가 자기 데이터와 함께
              동의하지 않은 상대방의 데이터를 올린다
```

업로더는 자기 대화라고 생각하지만, 그 캡처의 절반은 **상대방이 쓴 글**이다. 상대방은 자기 메시지가 분석 서버로 전송된다는 사실을 모른다.

이 사실에서 아래 원칙이 나온다.

- **최소 수집**: 분석에 필요한 것 이상을 받지 않는다
- **최소 보관**: 필요한 시간 이상 두지 않는다
- **최소 노출**: 원문을 로그·응답·제3자 서비스로 흘리지 않는다
- **명확한 고지**: 업로더가 무엇을 하고 있는지 알게 한다

기준 명세 5장의 데이터 처리 원칙, `AI-모델-선정-보고서.md` 3장의 무료 티어 배제가 모두 여기서 나온 결론이다.

## 3. 서비스 이용약관에 담을 내용

정식 법률 검토를 받기 전의 초안이다. **변호사 검토 없이 그대로 게시하지 않는다.**

### 3.1 서비스의 성격

- 본 서비스는 **오락 목적**의 관계 분석 도구다.
- 결과는 통계적 추정이며, 실제 인간관계를 판단하거나 평가하는 근거가 아니다.
- 결과를 근거로 한 어떤 결정에도 서비스는 책임지지 않는다.

### 3.2 이용자의 의무

- **본인이 참여한 대화만 업로드한다.**
- 타인의 대화를 몰래 촬영하거나 전달받아 업로드하지 않는다.
- 업로드한 대화에 상대방의 민감정보가 담기지 않도록 스스로 확인한다.
- 결과를 상대방을 조롱하거나 괴롭히는 데 쓰지 않는다.

### 3.3 금지 행위

- 자동화 도구를 이용한 대량 요청
- 서비스의 분석 결과를 상업적으로 재판매하는 행위
- 타인을 사칭해 업로드하는 행위

### 3.4 연령

- **만 14세 미만은 이용할 수 없다.** 법정대리인 동의 절차를 두지 않기로 했기 때문이다.
- 이 제한을 첫 화면에서 고지한다.

## 4. 개인정보 처리방침에 담을 내용

### 4.1 수집 항목

| 항목 | 수집 시점 | 보관 기간 | 목적 |
| --- | --- | --- | --- |
| 업로드 이미지 | 분석 요청 시 | **분석 종료 즉시 삭제** | OCR |
| 대화 텍스트(추출본) | 분석 중 | 분석 종료 즉시 삭제 | 관계 분석 |
| 분석 결과(점수·리포트) | 분석 완료 시 | **최대 20분** | 결과 조회 |
| 접속 IP | 요청 시 | 제한 창(최대 24시간) | 요청 제한 |

**계정 정보, 이름, 연락처, 쿠키 기반 식별자는 수집하지 않는다.**

### 4.2 수집하지 않는 것을 명시한다

무엇을 안 하는지도 함께 적는다. 사용자가 가장 걱정하는 부분이기 때문이다.

- 회원가입을 받지 않는다
- 분석 이력을 남기지 않는다
- 대화 원문을 로그에 남기지 않는다
- 대화 원문을 결과 응답에 담아 되돌려 보내지 않는다
- 업로드한 파일의 원래 이름을 저장하지 않는다

### 4.3 제3자 제공

분석 과정에서 아래 외부 서비스에 데이터가 전송된다. **이 목록은 실제 채택한 Provider에 맞춰 갱신해야 한다.**

| 대상 | 전송 데이터 | 목적 | 학습 이용 |
| --- | --- | --- | --- |
| OCR 제공자 | 업로드 이미지 | 텍스트 추출 | 하지 않는 곳만 채택 |
| LLM 제공자 | 추출된 대화 텍스트 | 관계 분석 | 하지 않는 곳만 채택 |

> **입력을 학습에 쓰거나 사람이 검토할 수 있는 제공자는 채택하지 않는다.** Gemini와 Mistral의 무료 티어가 여기에 해당한다. 근거는 `AI-모델-선정-보고서.md` 3장.

Provider를 바꿀 때는 **이 표와 개인정보 처리방침을 함께 고친다.** 코드만 바꾸고 고지를 방치하면 사실과 다른 안내가 된다.

### 4.4 파기

- 정상 종료: 삭제 요청 즉시 파기
- 비정상 종료: TTL 20분 경과 시 자동 파기
- 조회되지 않은 작업: 주기적 정리로 파기

파기는 되돌릴 수 없다. 백업을 두지 않는다.

### 4.5 이용자의 권리

계정이 없고 식별자를 저장하지 않으므로 **열람·정정·삭제 요청 대상이 되는 개인정보가 남지 않는다.** 다만 이용자는 결과 화면에서 언제든 즉시 삭제를 요청할 수 있다.

## 5. 화면에 노출할 고지

문서를 만들어 두는 것으로 끝나지 않는다. 사용자가 실제로 보는 자리에 있어야 한다.

| 위치 | 문구 | 구현 상태 |
| --- | --- | --- |
| 업로드 화면 | 임시 저장과 자동 삭제 안내 | **완료** |
| 모든 화면 하단 | "본인이 참여한 대화만 올려주세요. 재미로 보는 결과입니다." | **완료** |
| 결과 화면 | 고지 문구(`ReportData.disclaimer`) | **완료** |
| 결과 이미지 | 고지 문구를 카드에 새김 | **완료** |
| 업로드 화면 | 만 14세 이상 확인 (동의 체크박스) | **완료** |
| 업로드 화면 | 본인 참여 대화 확인 (동의 체크박스) | **완료** |
| 업로드 화면 | 이용약관·개인정보 처리방침 링크 | **자리 확보 완료, 문서 미작성** |

고지 문구는 서버가 주입하며 모델이 생성하지 않는다. 모델이 문구를 바꾸는 것을 막기 위해 `ReportAgent` 가 응답의 `disclaimer` 를 덮어쓴다.

## 6. 보안 조치

### 6.1 구현된 것

| 조치 | 내용 |
| --- | --- |
| 전송 구간 암호화 | HTTPS 전용 |
| 파일 형식 검증 | 확장자가 아니라 매직 넘버로 판별 |
| 최소 해상도 검증 | 320px 미만 거절 |
| 용량 제한 | 개별 5MB, 전체 20MB |
| 개수 제한 | 1~10장 |
| 요청 제한 | IP당 분당 5회, 일일 10회, 동시 3건 |
| 실행 시간 제한 | 전체 180초, OCR 60초, LLM 45초 |
| 접근 제어 | `jobId`(UUID v4)를 아는 클라이언트만 조회 가능 |
| 프롬프트 인젝션 방어 | 대화를 구분자로 감싸고 내부 지시를 따르지 않도록 지시 |
| 원문 로그 차단 | 로그에 집계값과 식별자만 남김 |
| CORS | 서비스 도메인만 허용, 와일드카드 금지 |
| 오류 메시지 | 원문·파일명·식별자를 담지 않음 |
| 보안 헤더 | nosniff, DENY 프레임, no-referrer, CSP `default-src 'none'`, Permissions-Policy |
| 캐시 금지 | `Cache-Control: no-store`. 결과가 중간 캐시에 남으면 TTL이 무의미해진다 |
| HSTS | HTTPS 요청에만 부여 (프록시의 `X-Forwarded-Proto` 판별) |

### 6.2 남은 것

| 조치 | 왜 필요한가 | 시점 |
| --- | --- | --- |
| **API 키 관리** | 현재 환경변수. 배포 시 시크릿 매니저로 옮긴다 | 배포 전 |
| **CORS 도메인 설정** | 기본값이 비어 있다. 실제 도메인을 넣어야 한다 | 배포 전 |
| **HTTPS 강제 리다이렉트** | 배포 플랫폼 설정 | 배포 전 |
| 이미지 폭탄 방어 | 압축률이 비정상적으로 높은 이미지(디컴프레션 밤) | 볼륨 증가 시 |
| 감사 로그 | 원문 없이 요청 패턴만 | 볼륨 증가 시 |

### 6.3 알려진 한계

정직하게 적어둔다. 감춰서 이득 볼 것이 없다.

- **IP 기반 제한은 공용 네트워크에서 부정확하다.** 같은 와이파이의 여러 사용자가 한 IP로 묶인다. 반대로 IP를 바꾸면 제한을 우회할 수 있다. 계정이 없는 서비스의 구조적 한계다.
- **`jobId` 가 유출되면 결과를 볼 수 있다.** UUID v4라 추측은 사실상 불가능하지만, 링크를 공유하면 TTL 동안 누구나 열 수 있다.
- **단일 인스턴스 전제다.** 작업 상태와 제한 카운터가 프로세스 메모리에 있다. 인스턴스를 늘리면 상태가 갈라진다.
- **업로더가 상대방 동의를 받았는지 확인할 방법이 없다.** 고지와 약관으로 책임을 명확히 하는 것 외에 기술적 수단이 없다.

## 7. 사고 대응

| 상황 | 대응 |
| --- | --- |
| API 키 유출 | 즉시 폐기·재발급, 사용량 확인 |
| 비용 폭주 | 제한값을 낮추거나 서비스를 일시 중단. 예산 알림을 미리 걸어둔다 |
| 원문이 로그에 남은 것을 발견 | 해당 로그 즉시 파기, 원인 코드 수정, 재발 방지 테스트 추가 |
| 제공자가 데이터 정책을 변경 | 즉시 다른 Provider로 전환. 그래서 교체 가능한 구조로 만들었다 |
| 대량 악성 업로드 | 요청 제한 강화, 필요 시 업로드 차단 |

**Provider 교체가 사고 대응 수단이라는 점이 중요하다.** 특정 업체에 코드가 묶여 있으면 정책이 바뀌었을 때 서비스를 멈추는 것 외에 선택지가 없다.
