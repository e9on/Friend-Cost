# 친구비 측정기 — Frontend 명세서

| 항목 | 값 |
| --- | --- |
| 버전 | v1.0 |
| 최종 수정일 | 2026-08-25 |
| 상위 문서 | `친구비-측정기-서비스-기준-명세.md` |
| 인터페이스 | `API-명세.md` |
| 데이터 구조 | `데이터-계약-명세.md` |

## 1. 문서 목적

이 문서는 웹 클라이언트의 **화면 구성, 상태 전이, 사용자에게 지켜야 할 약속**을 정의한다.

색이나 여백 같은 시각적 세부는 다루지 않는다. 그건 코드가 진실이다. 여기 적는 것은 **바꾸면 안 되는 것**이다.

## 2. 전제

| 항목 | 값 |
| --- | --- |
| 기반 | React + TypeScript, Vite |
| 배포 | 정적 호스팅 (기준 명세 8장) |
| 화면 기준 | **모바일 우선** |
| 인증 | 없음 |
| 저장소 | 없음. localStorage도 쓰지 않는다 |

**모바일 우선인 이유**는 취향이 아니다. 대화 캡처는 휴대폰에서 찍고, 결과도 휴대폰에서 보고, 공유도 휴대폰에서 한다. 데스크톱은 폭만 제한하면 되는 부수적 경우다.

**localStorage를 쓰지 않는 이유**는 기준 명세 5장이다. 남길 것이 없다.

## 3. 화면 흐름

```text
    업로드
      │ 분석 시작
      ▼
    진행  ◄── 폴링
      │
      ├── 완료 ──▶ 결과 ──▶ (다시 하기) ──▶ 업로드
      │
      └── 실패 ──▶ 실패 ──▶ (다시 하기) ──▶ 업로드
```

| 상태 | 의미 |
| --- | --- |
| `idle` | 업로드 화면 |
| `uploading` | 이미지 전송 중 |
| `running` | 서버가 분석 중. 폴링 |
| `done` | 결과 표시 |
| `failed` | 실패 안내 |

상태는 훅 하나(`useAnalysis`)가 소유한다. 화면은 상태를 읽어 그리기만 한다.

## 4. 업로드 화면

### 4.1 사전 검증

서버가 다시 검증하지만 여기서 먼저 거른다. **헛된 왕복을 줄이기 위해서다.**

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 개수 | 1~10장 | `API-명세.md` 4장 |
| 형식 | PNG, JPG, WEBP | 같은 곳 |
| 개별 용량 | 5MB | 같은 곳 |
| 전체 용량 | 20MB | 같은 곳 |

**이 값이 서버와 어긋나면 사용자는 서버에 가서야 거절당한다.** API 명세가 바뀌면 여기도 함께 고친다.

해상도는 검사하지 않는다. 브라우저에서 재려면 이미지를 모두 디코드해야 해서 느리다. 서버가 헤더로 판별한다.

### 4.2 이미지 순서

**업로드 순서가 곧 시간 순서다.** 사용자에게 이 사실을 알린다.

- 각 미리보기에 순번을 표시한다
- "번호 순서대로 시간이 흐른다고 봅니다"를 문구로 노출한다

순서가 뒤바뀌면 시각 복원이 어긋나 결과가 통째로 틀어진다. 조용히 두면 사용자는 알 수 없다.

### 4.3 필수 동의

분석 시작 전에 확인시킨다.

> 내가 참여한 1:1 대화이고, 만 14세 이상입니다.

체크하지 않으면 시작 버튼이 잠긴다. 근거는 `운영-보안-법적고지-명세.md` 3장.

**이것이 상대방의 동의를 보장하지는 않는다.** 기술로 확인할 방법이 없다. 업로더가 무엇을 하고 있는지 자각하게 하는 것이 할 수 있는 전부다.

### 4.4 사전 고지

업로드 **전에** 데이터가 어떻게 다뤄지는지 알린다. 결과를 본 뒤에 알리면 늦다.

- 올린 이미지는 분석이 끝나는 즉시 삭제
- 결과는 20분 뒤 자동 삭제
- 계정도 기록도 없음
- 이용약관·개인정보 처리방침 링크

## 5. 진행 화면

### 5.1 폴링

- **서버가 준 `pollAfterSeconds` 를 따른다.** 클라이언트가 임의로 정하지 않는다.
- 값이 없으면 2초로 대신한다.
- 서버가 `done` 이면 결과를 받아온다. `failed` 면 오류를 표시한다.

### 5.2 진행률

`stage` 를 단계별 백분율에 대응시킨다.

| 단계 | 표시 | 진행률 |
| --- | --- | ---: |
| — (업로드 중) | 캡처를 올리는 중 | 8 |
| — (단계 미상) | 분석을 준비하는 중 | 12 |
| `ocr` | 대화를 읽는 중 | 20 |
| `parsing` | 메시지를 정리하는 중 | 35 |
| `analyzing` | 관계를 살펴보는 중 | 60 |
| `scoring` | 점수를 계산하는 중 | 75 |
| `reporting` | 리포트를 쓰는 중 | 90 |

**이 값은 실제 완료 비율이 아니다.** 목적은 정확한 예측이 아니라 "멈추지 않았다"를 보여주는 것이다. 단계를 모르는 동안에도 0%를 보여주지 않는다.

### 5.3 취소

두지 않는다. 분석은 수십 초면 끝나고, 취소 버튼은 사용자가 이탈로 해결할 수 있는 문제를 UI로 옮길 뿐이다. 이탈하면 삭제 요청이 나간다.

## 6. 결과 화면

### 6.1 표시 항목

| 항목 | 강조 |
| --- | --- |
| 친구비 | **가장 크게.** 서비스의 대표 지표다 |
| 헤드라인 | 그다음 |
| 요약 | 본문 |
| 지표 6종 | 격자 |
| 리포트 단락 2~3개 | 본문 |
| 제안 | 강조 상자 |
| 메타 (메시지 수, 기간, 신뢰도) | 작게 |
| 고지 문구 | 맨 아래, 반드시 |

### 6.2 `null` 을 0으로 뭉개지 않는다

`avgReplySeconds` 는 표본이 부족하면 `null` 이다. 이때 **"알 수 없음"으로 표시한다.**

`0초`로 보이면 "즉시 답장하는 사이"라는 정반대의 뜻이 된다. 서버가 굳이 `null` 을 구분해 보내는 이유가 여기 있다.

### 6.3 신뢰도 경고

`confidence` 가 `high` 가 아니면 안내를 덧붙인다.

| 값 | 문구 |
| --- | --- |
| `high` | (없음) |
| `medium` | 대화량이 넉넉하지 않아 결과가 흔들릴 수 있어요 |
| `low` | 분석할 대화가 적어 결과를 참고만 해주세요 |

`meta.sampled` 가 `true` 면 일부만 분석했다는 사실도 알린다.

**낮은 신뢰도를 숨기지 않는다.** 숫자만 보여주면 사용자는 그것이 정확하다고 믿는다.

### 6.4 결과 이미지 저장

**서버에 다운로드 엔드포인트가 없다.** 브라우저가 직접 그린다(기준 명세 11장).

- 캔버스에 직접 그린다. DOM 캡처 라이브러리를 쓰지 않는다.
- 이유: 의존성 없이 어느 브라우저에서나 같은 결과가 나온다. 폰트 로딩이나 CSS 해석 차이로 이미지가 깨지지 않는다.
- 카드에는 친구비, 지표 6종, 헤드라인, 요약, **고지 문구**를 담는다.
- 모바일에서는 공유 시트를 먼저 시도한다. `<a download>` 이 무시되는 경우가 있기 때문이다.
- 공유를 취소하면 저장으로 넘어간다.
- 실패하면 "화면을 캡처해 주세요"로 안내한다. 조용히 아무 일도 일어나지 않게 두지 않는다.

### 6.5 TTL 카운트다운

`expiresAt` 까지 남은 시간을 초 단위로 보여준다.

만료되면 문구를 바꾼다.

> 결과가 서버에서 삭제되었어요. 저장한 이미지는 그대로 남아 있습니다.

사용자가 손해를 봤다고 느끼지 않게 하는 것이 목적이다. 실제로 저장한 이미지는 남아 있다.

## 7. 실패 화면

### 7.1 오류 코드마다 다른 안내

`error.code` 로 분기한다. **원인마다 사용자가 할 수 있는 일이 다르기 때문이다.**

| 코드 | 다시 시도 권유 |
| --- | --- |
| `TOO_FEW_MESSAGES` | **하지 않는다.** 같은 캡처로는 같은 결과다 |
| `NO_CONVERSATION_FOUND` | 하지 않는다 |
| `GROUP_CHAT_DETECTED` | 하지 않는다 |
| `SPEAKER_DETECTION_FAILED` | 하지 않는다 |
| `IMAGE_*` | 하지 않는다 |
| `DAILY_LIMIT_EXCEEDED` | 하지 않는다 |
| `JOB_EXPIRED` | 하지 않는다 |
| `RATE_LIMITED` | 한다 |
| `CONCURRENCY_LIMIT` | 한다 |
| `ANALYSIS_TIMEOUT` | 한다 |
| `NETWORK_ERROR` | 한다 |
| 그 밖 | `retryable` 을 따른다 |

대화가 짧아 실패한 사람에게 "다시 시도"를 권하면 같은 결과만 반복된다. 무엇을 고쳐야 하는지 알려주는 편이 낫다.

### 7.2 모르는 코드

서버가 새 오류 코드를 추가해도 화면이 깨지지 않아야 한다. 기본 안내를 보여주고 `retryable` 을 따른다.

### 7.3 오류 코드 노출

문의에 쓸 수 있도록 코드를 작게 표시한다. 다만 `jobId` 는 노출하지 않는다.

## 8. 임시 데이터 정리

클라이언트도 삭제 책임을 진다.

| 시점 | 동작 |
| --- | --- |
| "다른 대화 분석하기" | `DELETE /v1/analyses/{jobId}` |
| 페이지 이탈 (`pagehide`) | `sendBeacon` 으로 `POST .../deletion` |
| 컴포넌트 언마운트 | 같음 |

`sendBeacon` 을 쓰는 이유는 **이탈 중에는 일반 요청이 취소되기 때문**이다. `sendBeacon` 은 POST만 보낼 수 있어서 서버가 별도 경로를 열어 두었다.

**삭제 요청이 실패해도 사용자에게 알리지 않는다.** 도달하지 못하면 서버의 TTL이 대신 지운다. 떠나는 사람에게 오류를 띄울 이유가 없다.

## 9. 접근성

| 항목 | 처리 |
| --- | --- |
| 진행률 | `role="progressbar"` 와 `aria-valuenow` |
| 이미지 제거 버튼 | `aria-label` 로 몇 번째인지 알림 |
| 미리보기 이미지 | 순번을 담은 `alt`. 빈 `alt` 를 쓰지 않는다 |
| 장식 요소 | `aria-hidden` |
| 애니메이션 | `prefers-reduced-motion` 존중 |
| 색상 | 어두운 배경 기준. 대비 확보 |

미리보기 이미지에 빈 `alt` 를 쓰지 않는 이유는, 그것이 **어떤 캡처를 골랐는지 알려주는 의미 있는 정보**이기 때문이다. 장식이 아니다.

## 10. 오류·경계 처리

| 상황 | 처리 |
| --- | --- |
| 네트워크 단절 | `NETWORK_ERROR` 로 서버 오류와 구분 |
| 서버가 오류 봉투가 아닌 응답 | 네트워크 오류로 접어 안내 |
| 폴링 중 실패 | 실패 화면으로. 무한 폴링하지 않는다 |
| 캔버스를 못 쓰는 환경 | 터지지 않고 저장 실패로 안내 |
| 언마운트 후 응답 도착 | 상태를 갱신하지 않는다 |

## 11. 하지 않는 것

의도적으로 넣지 않은 것들이다. 나중에 "왜 없지?"라는 질문에 답하기 위해 적어둔다.

- **결과 공유 링크**: 서버에 결과가 20분만 있고, 링크를 아는 사람이 열 수 있게 되어 개인정보 위험이 생긴다
- **분석 이력**: 기준 명세 3장의 제외 항목
- **로그인**: 같음
- **다크/라이트 전환**: 어두운 테마로 고정. 결과 카드 색과 맞추기 위해서다
- **다국어**: 카카오톡 한국어 대화가 대상이다
- **취소 버튼**: 5.3 참조
