# 친구비 측정기 — 데이터 계약 명세서

| 항목 | 값 |
| --- | --- |
| 버전 | v1.3 |
| 최종 수정일 | 2026-08-25 |
| 상위 문서 | `친구비-측정기-서비스-기준-명세.md` |

## 1. 문서 목적

이 문서는 친구비 측정기의 **모든 데이터 구조, 필드명, 상태값, 오류 코드를 정의하는 단일 진실 원천(Single Source of Truth)** 이다.

API 명세, 관계 점수 계산 규칙, OCR·Parser 명세, Backend 구현은 **여기에 정의된 이름과 타입을 그대로 사용한다.** 같은 개념을 다른 이름으로 재정의하지 않는다. 구조 변경이 필요하면 이 문서를 먼저 고치고 나머지를 따라 고친다.

## 2. 공통 규칙

| 구분 | 규칙 |
| --- | --- |
| 필드 표기 | camelCase |
| 시간 길이 | 초 단위 정수 (`Seconds` 접미사) |
| 시각 | Unix epoch 초 단위 정수 (UTC) |
| 금액 | 원 단위 정수 |
| 비율 | 0.0 ~ 1.0 실수, 소수 셋째 자리 반올림 |
| 점수 | 0 ~ 100 정수 |
| 화자 | `"me"` (업로더 본인) 또는 `"peer"` (상대방) |
| 미확정 값 | `null` (빈 문자열이나 `-1`을 쓰지 않는다) |

## 3. 파이프라인 데이터 흐름

```text
업로드 이미지
  ↓  OCR
OcrPage[]
  ↓  Conversation Parser
ConversationData
  ↓  Analysis Agent (LLM 1회)
RelationshipAnalysisData
  ↓  Relationship Algorithm (코드)
RelationshipScoreData
  ↓  Report Agent (LLM 1회)
ReportData
  ↓  API 응답
AnalysisResult
```

각 단계의 산출물은 다음 단계의 유일한 입력이다. 뒤 단계가 앞 단계를 건너뛰고 원본 데이터에 접근하지 않는다.

**단, Report Agent는 대화 원문(`ConversationData.messages`)을 입력으로 받지 않는다.** `RelationshipAnalysisData`와 `RelationshipScoreData`만 받는다. 입력 토큰을 줄이기 위한 의도적 제약이다.

## 4. OcrPage / OcrBlock

OCR 단계는 이미지 한 장당 `OcrPage` 하나를 만든다.

**`box` 좌표와 `width`는 필수다.** 화자 판별이 좌우 여백 비교에 의존하므로, 좌표를 제공하지 않거나 이미지 크기를 알 수 없는 OCR 엔진은 채택할 수 없다.

```json
{
  "imageIndex": 0,
  "width": 1080,
  "height": 2340,
  "blocks": [
    {
      "text": "내일 시간 돼?",
      "box": { "x": 612, "y": 830, "w": 396, "h": 44 },
      "confidence": 0.97
    }
  ]
}
```

`OcrPage`

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `imageIndex` | int | 업로드 순서 기준 0-based 이미지 번호 |
| `width` | int | 이미지 원본 너비(픽셀). 좌우 판별의 기준값 |
| `height` | int | 이미지 원본 높이(픽셀) |
| `blocks` | OcrBlock[] | 이 이미지에서 인식된 블록 |

`OcrBlock`

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `text` | string | 인식된 텍스트 |
| `box` | object | 이미지 좌상단(0,0) 기준 픽셀 좌표 |
| `box.x` | int | 좌측 경계 |
| `box.y` | int | 상단 경계 |
| `box.w` | int | 너비 |
| `box.h` | int | 높이 |
| `confidence` | float | 0.0 ~ 1.0 인식 신뢰도 |

`imageIndex`는 `OcrPage`에만 두고 `OcrBlock`에는 두지 않는다. 같은 값을 두 곳에 두면 어긋날 수 있다.

## 5. Message

정규화된 개별 메시지.

```json
{
  "index": 12,
  "speaker": "me",
  "text": "내일 시간 돼?",
  "sentAt": 1755500460,
  "timeSource": "explicit",
  "imageIndex": 0
}
```

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `index` | int | 시간순 0-based 일련번호 |
| `speaker` | `"me"` \| `"peer"` | 화자 |
| `text` | string | 정규화된 본문 |
| `sentAt` | int \| null | Unix epoch 초. 복원 실패 시 `null` |
| `timeSource` | enum | 아래 표 참조 |
| `imageIndex` | int | 이 메시지가 추출된 이미지 번호 |

`timeSource` 값:

| 값 | 의미 |
| --- | --- |
| `explicit` | 캡처에 시각이 표시되어 있고 날짜 앵커로 절대 시각 확정 |
| `inferred` | 시각은 있으나 날짜를 추론으로 보정 |
| `unknown` | 시각 복원 실패. `sentAt`은 `null` |

## 6. ConversationData

Parser의 최종 산출물이자 Analysis Agent의 유일한 입력.

```json
{
  "messages": [ ],
  "meta": {
    "imageCount": 5,
    "messageCount": 184,
    "droppedCount": 23,
    "sampled": false,
    "timeCoverage": 0.91,
    "spanSeconds": 1209600
  }
}
```

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `messages` | Message[] | 시간순 정렬 |
| `meta.imageCount` | int | 업로드된 이미지 수 |
| `meta.messageCount` | int | 정규화 후 메시지 수 |
| `meta.droppedCount` | int | 중복·시스템 메시지로 제거된 수 |
| `meta.sampled` | bool | 토큰 한도로 샘플링되었는지 |
| `meta.timeCoverage` | float | `sentAt`이 `null`이 아닌 메시지 비율 |
| `meta.spanSeconds` | int \| null | 첫 메시지와 마지막 메시지의 간격 |

## 7. RelationshipAnalysisData

Analysis Agent(LLM 1회)의 출력. **모든 값은 정수 또는 문자열 배열이며, LLM은 점수·비율·평균을 계산하지 않는다.** 여기서 나오는 값은 "의미 판단"이고, 최종 지표는 다음 단계에서 코드가 계산한다.

```json
{
  "emotionalTone":    { "me": 72, "peer": 65 },
  "affectionSignals": { "me": 58, "peer": 41 },
  "effortLevel":      { "me": 70, "peer": 45 },
  "conflictLevel": 18,
  "topicDepth": 62,
  "promiseSignals": { "proposed": 6, "fulfilled": 4, "declined": 2 },
  "moneySignals":   { "lent": 1, "borrowed": 0, "resolved": 0 },
  "notableMoments": ["생일 축하를 먼저 챙김", "약속 취소가 두 번 반복됨"]
}
```

| 필드 | 타입 | 범위 | 설명 |
| --- | --- | --- | --- |
| `emotionalTone.me` / `.peer` | int | 0~100 | 대화에서 드러난 감정 온도. 높을수록 긍정적 |
| `affectionSignals.me` / `.peer` | int | 0~100 | 애정·친근 표현의 강도 |
| `effortLevel.me` / `.peer` | int | 0~100 | 대화를 이어가려는 노력의 정도 |
| `conflictLevel` | int | 0~100 | 갈등·냉랭함의 정도 |
| `topicDepth` | int | 0~100 | 대화 주제의 깊이 (잡담 ↔ 속내) |
| `promiseSignals.proposed` | int | 0~ | 약속 제안 건수 |
| `promiseSignals.fulfilled` | int | 0~ | 성사된 약속 건수 |
| `promiseSignals.declined` | int | 0~ | 거절·취소된 약속 건수 |
| `moneySignals.lent` | int | 0~ | 내가 빌려준 정황 건수 |
| `moneySignals.borrowed` | int | 0~ | 내가 빌린 정황 건수 |
| `moneySignals.resolved` | int | 0~ | 정산·상환이 확인된 건수 |
| `notableMoments` | string[] | 최대 5개 | 각 60자 이하. 인용이 아니라 요약이어야 한다 |

`notableMoments`에 **대화 원문을 그대로 옮겨 적지 않는다.** 기준 명세 5장의 원문 보호 원칙에 따라 요약된 서술만 허용한다.

## 8. RelationshipScoreData

Relationship Algorithm(일반 코드)의 출력. 산식은 `관계-점수-계산-규칙.md`가 정의한다. 이 문서는 **구조와 단위만** 정의한다.

```json
{
  "friendFee": -36000,
  "intimacy": 64,
  "breakupRisk": 38,
  "firstContactRatio": 0.63,
  "avgReplySeconds": { "me": 420, "peer": 1860 },
  "contactBalance": 74
}
```

| 필드 | 타입 | 범위 | 설명 |
| --- | --- | --- | --- |
| `friendFee` | int | **-100000 ~ 100000** | 친구비. 1000원 단위. **부호가 뜻을 갖는다.** 양수면 상대가 나에게, 음수면 내가 상대에게 낼 몫이다. 관계가 나쁘다는 뜻이 아니라 **누가 더 기여했는가**를 나타낸다 |
| `intimacy` | int | 0~100 | 친밀도 |
| `breakupRisk` | int | 0~100 | 손절 위험도 |
| `firstContactRatio` | float | 0.0~1.0 | **내가** 먼저 연락한 대화 세션의 비율 |
| `avgReplySeconds.me` | int \| null | 0~ | 내가 답장하기까지 걸린 평균 시간. 표본 3개 미만이면 `null` |
| `avgReplySeconds.peer` | int \| null | 0~ | 상대가 답장하기까지 걸린 평균 시간. 표본 3개 미만이면 `null` |
| `contactBalance` | int | 0~100 | 연락 균형도. 100이 완전 균형 |

**`confidence`(결과 신뢰도)는 두지 않는다.** 2026-08-27 제거했다.

이 서비스는 재미로 읽는 결과다. 등급을 붙이면 사용자는 그것을 **결과의 정확도**로 읽는데, 실제로 등급을 끌어내리던 것은 관계가 아니라 **우리 OCR 품질**이었다. 실측에서 메시지 120개·세션 3개로 조건을 다 채우고도 `low` 가 나왔다. 시각 복원 비율이 32.5%였기 때문이고, 그 이유는 어두운 테마 캡처에서 OCR 이 `9:40` 의 콜론을 놓쳐 대부분의 시각을 버렸기 때문이다.

사용자에게는 그 구분이 보이지 않는다. "낮음"만 보이고, 자기 관계가 부실하다고 읽는다. **우리 쪽 문제를 사용자의 결과에 등급으로 붙여서는 안 된다.**

대신 표본이 정말 적을 때만 한 줄을 띄운다(`Frontend-명세.md` 6.4). 그 판단은 `meta.messageCount` 로 화면이 한다. 시각 복원 비율은 기준에서 뺐다. 사용자가 어찌할 수 없는 값이다.

## 9. ReportData

Report Agent(LLM 1회)의 출력. **글자 수 상한은 출력 토큰 비용을 통제하기 위한 규격이며 권고가 아니라 제약이다.**

```json
{
  "headline": "서로 챙기지만 균형이 조금 기운 사이",
  "summary": "...",
  "sections": [
    { "title": "연락의 흐름", "body": "..." },
    { "title": "지켜볼 지점", "body": "..." }
  ],
  "advice": "...",
  "disclaimer": "이 결과는 재미를 위한 추정이며 실제 관계를 판단하는 근거가 아닙니다."
}
```

| 필드 | 타입 | 상한 | 설명 |
| --- | --- | --- | --- |
| `headline` | string | 40자 | 한 줄 요약 |
| `summary` | string | 200자 | 전체 요약 |
| `sections` | object[] | 2~3개 | 본문 단락 |
| `sections[].title` | string | 20자 | 단락 제목 |
| `sections[].body` | string | 300자 | 단락 본문 |
| `advice` | string | 150자 | 관계를 위한 제안 |
| `disclaimer` | string | 고정 | 서버가 주입하는 고정 문구. LLM이 생성하지 않는다 |

Report Agent는 `RelationshipScoreData`의 숫자를 **재계산하거나 변형하지 않는다.** 언급할 때는 전달받은 값을 그대로 인용한다.

## 10. 작업 상태 모델

```json
{
  "jobId": "9f2a7c14-3b8e-4d51-a0c6-7e2f5b91d834",
  "status": "processing",
  "stage": "analyzing",
  "expiresAt": 1755502260
}
```

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `jobId` | string | UUID v4. 추측 불가능한 값이어야 한다 |
| `status` | enum | 아래 표 참조 |
| `stage` | enum \| null | `status`가 `processing`일 때만 존재 |
| `expiresAt` | int | Unix epoch 초. TTL 만료 시각 |

`status` 값:

| 값 | 의미 | 다음 상태 |
| --- | --- | --- |
| `pending` | 접수됨, 처리 대기 | `processing`, `failed`, `expired` |
| `processing` | 처리 중 | `done`, `failed`, `expired` |
| `done` | 완료, 결과 조회 가능 | `expired` |
| `failed` | 실패. `error` 필드 존재 | `expired` |
| `expired` | TTL 만료, 데이터 삭제됨 | (종료) |

`stage` 값: `ocr` → `parsing` → `analyzing` → `scoring` → `reporting`

## 11. 오류 코드

모든 오류 응답은 아래 형태를 따른다.

```json
{
  "error": {
    "code": "TOO_FEW_MESSAGES",
    "message": "분석하기에 대화가 너무 짧습니다.",
    "retryable": false
  }
}
```

`message`에는 **대화 원문이나 파일명을 넣지 않는다.**

| 코드 | HTTP | 재시도 | 설명 |
| --- | ---: | --- | --- |
| `IMAGE_TOO_MANY` | 400 | 불가 | 이미지 개수 초과 |
| `IMAGE_TOO_LARGE` | 400 | 불가 | 개별 또는 전체 용량 초과 |
| `IMAGE_FORMAT_UNSUPPORTED` | 400 | 불가 | 허용되지 않은 형식 |
| `OCR_FAILED` | 422 | 가능 | OCR 처리 실패 |
| `NO_CONVERSATION_FOUND` | 422 | 불가 | 대화로 인식되는 내용이 없음 |
| `TOO_FEW_MESSAGES` | 422 | 불가 | 최소 메시지 수 미달 |
| `GROUP_CHAT_DETECTED` | 422 | 불가 | 단체 대화방으로 판별됨 |
| `SPEAKER_DETECTION_FAILED` | 422 | 불가 | 좌우 화자 판별 불가 |
| `LLM_FAILED` | 502 | 가능 | LLM 호출 실패 |
| `LLM_SCHEMA_INVALID` | 502 | 가능 | 재시도 후에도 스키마 불일치 |
| `RATE_LIMITED` | 429 | 가능 | IP 기준 요청 빈도 초과 |
| `DAILY_LIMIT_EXCEEDED` | 429 | 불가 | **이 IP의** 일일 분석 횟수 초과 |
| `SERVICE_DAILY_LIMIT` | 429 | 불가 | **서비스 전체의** 하루 분량 소진 |
| `SERVICE_ENDED` | 410 | 불가 | 운영 종료일이 지나 새 분석을 받지 않음 |
| `CONCURRENCY_LIMIT` | 429 | 가능 | 동시 분석 한도 초과 |
| `JOB_NOT_FOUND` | 404 | 불가 | 존재하지 않는 작업 |
| `JOB_EXPIRED` | 410 | 불가 | TTL 만료로 삭제됨 |
| `JOB_NOT_READY` | 409 | 가능 | 아직 완료되지 않음 |
| `ANALYSIS_TIMEOUT` | 504 | 가능 | 실행 시간 제한 초과 |
| `BAD_REQUEST` | 400 | 불가 | 요청 형식이 규격에 맞지 않음 |
| `INTERNAL_ERROR` | 500 | 가능 | 그 밖의 서버 오류 |

### 11.1 프레임워크가 만든 오류

요청이 라우트에 닿기도 전에 거절되는 경우가 있다. 본문이 JSON 이 아니거나, 필드가 빠졌거나, 값이 열거형에 없을 때다. 이때는 우리 코드가 오류를 고르지 못하므로 HTTP 상태로 매핑한다.

| 상태 | 코드 |
| --- | --- |
| 400, 422 | `BAD_REQUEST` |
| 404, 405 | `JOB_NOT_FOUND` |
| 409 | `JOB_NOT_READY` |
| 410 | `JOB_EXPIRED` |
| 413 | `IMAGE_TOO_LARGE` |
| 429 | `RATE_LIMITED` |

**400·422 를 `IMAGE_FORMAT_UNSUPPORTED` 로 두지 않는다.** 예전에는 본문을 받는 엔드포인트가 업로드뿐이라 그렇게 두어도 맞았다. `POST /v1/events` 가 생기면서 틀린 말이 됐다 — 이벤트 이름이 잘못됐는데 "지원하지 않는 이미지 형식입니다"가 나갔다.

이미지 형식 문제는 업로드 검증기가 직접 `IMAGE_FORMAT_UNSUPPORTED` 를 던진다. 이 표는 **프레임워크가 만든 오류**에만 쓰인다.

## 12. AnalysisResult

결과 조회 API의 응답 본문.

```json
{
  "jobId": "9f2a7c14-3b8e-4d51-a0c6-7e2f5b91d834",
  "scores": { },
  "report": { },
  "meta": {
    "messageCount": 184,
    "imageCount": 5,
    "sampled": false,
    "spanSeconds": 1209600
  },
  "expiresAt": 1755502260
}
```

`meta`는 `ConversationData.meta`의 부분집합이다. **`RelationshipAnalysisData`와 `ConversationData.messages`는 응답에 포함하지 않는다.** 대화 원문이 클라이언트로 되돌아가지 않게 하기 위한 제약이다.

## 12-1. 사용 이벤트

화면에서 서버로 보내는 **식별자 없는 집계 신호**다. 어디서 이탈하는지 알기 위한 것이고, 개인을 이어붙이지 않는다.

서버는 분석 요청이 들어와야만 안다. 그 전에 떠난 사람은 흔적이 없다. 이탈 지점이 정확히 거기이므로 화면이 알려줘야 한다.

| 이름 | 언제 |
| --- | --- |
| `page.view` | 화면에 처음 들어옴 |
| `consent.agreed` | 최초 입장 동의를 마침 |
| `upload.selected` | 이미지를 골랐음 |
| `result.viewed` | 결과 화면에 도달 |
| `result.shared` | 친구에게 공유를 누름 |
| `result.saved` | 결과 이미지 저장을 누름 |

**이름은 서버가 정한 목록만 받는다.** 아무 문자열이나 받으면 로그가 오염되고, 그 자체가 대화 원문이 새는 통로가 된다.

분석 시작·성공·실패는 여기 없다. 서버가 이미 안다(`운영-보안-법적고지-명세.md` 6.2). 같은 것을 두 곳에서 세면 숫자가 어긋난다.

**세션 식별자를 두지 않는다.** 그래서 "방문 100, 동의 60" 은 알아도 "그 60명이 누구인가"는 모른다. 개인을 이어붙이려면 식별자를 심어야 하고, 그것은 이 서비스가 하지 않기로 한 일이다.
